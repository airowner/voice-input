# 模型管理实现与验证边界

`crates/runtime/src/models.rs` 负责单文件模型导入、内置清单下载、不可变版本发布和引用保护。此模块的模拟验证闭包测试不代表真实引擎加载已经通过；真实 load 证据由 worker 验证流程单独提供。

## 发布顺序

1. 检查大小（1 KiB 至 16 GiB）、磁盘空间及 256 MiB 系统余量。本地源复制到模型目录同卷的私有 `.voice-model-*.part`；下载直接写同卷 part。
2. 计算完整 SHA-256。下载必须与 `models.lock.json` 中固定大小、哈希一致。
3. 检查 GGUF / Whisper magic，调用实际 worker 加载验证闭包，然后再次全文件哈希，拒绝加载过程中发生变化的文件。
4. 在目录 mutation lock 下再次确认 index 未被外部修改，以 `persist_noclobber` 发布内容哈希命名的模型，禁止覆盖已有文件。崩溃遗留的同名文件只能在完整字节一致时接纳。
5. 刷盘临时 index 后原子替换 index，再刷目录。index 已提交后的目录刷盘失败会保留被引用模型和内存条目，并返回明确的不确定错误，不能回滚删除模型而留下悬空 index。

相同模型再次导入仍执行加载闭包和完整校验；不依赖旧缓存跳过实际兼容验证。选用模型或有 `Arc<ModelRecord>` 运行引用的模型禁止删除。删除先提交不再引用它的 index，之后删除文件；后者失败会报告“目录已更新，但模型文件删除失败”，不会重新把未确认的文件加入目录。

## 目录和崩溃恢复

index 超限、JSON 损坏、路径逃逸、重复 ID / 文件名、非法元数据、文件 symlink、格式或完整哈希不符均拒绝打开，不以空目录覆盖。运行期间 index 字节版本改变也拒绝后续提交。

模型目录不能是 symlink，索引文件及索引中的模型路径也不能是 symlink。index 文件名必须是单个普通组件，拒绝绝对路径、父目录、Windows 分隔符和驱动器形式。

所有 part 文件持有独占文件锁。打开有效模型目录后，清理仅限本模块命名且未被锁定的崩溃遗留 part；正在导入/下载的 part 和用户其他 `.part` 文件保留。目录 mutation lock 保护创建+加锁、发布、index 提交、回滚和删除的边界，避免并发会话互删文件。

## 下载与取消

仅接受内置 ID，无自定义 URL。初始地址须为无用户信息、无 query/fragment、443 端口的官方 Hugging Face HTTPS 地址。重定向仅允许 `huggingface.co` / `hf.co` 及其子域的 HTTPS，允许官方签名 query，仍拒绝用户信息、片段和非 443 端口，最多五次重定向。不读取代理环境变量，无自动应用级重试。

单次 GET 的网络线程以 64 KiB chunk 和容量 2 的 channel 提供数据；调用线程每 25 ms 检查取消、总时限、长度和磁盘写入。取消后立即释放接收端和 part，网络线程下一次发送会结束。正在阻塞的请求头/读取等待由 reqwest 的 5 秒操作超时约束，线程清理可能比界面取消稍晚；不会让界面等待 1800 秒的 body read。总下载时限仍为 1800 秒。取消也在完整哈希和加载闭包前后检查。

## 确定性测试范围

单测仅使用临时文件和验证闭包，不访问真实模型目录、不下载网络资源。覆盖完整字节哈希、格式失败、加载失败与加载期间修改、下载哈希不符、大小上限、磁盘余量和整数溢出、发布位置冲突不覆盖、损坏 index 不覆盖、路径逃逸和 symlink、重复条目、选用/运行引用保护、崩溃 part 与活动 part 区分、阻塞下载取消、长度不符和官方域策略。

实际测试命令及通过结果由主代理收集；未经运行的检查不能视为通过。真实 TLS 重定向、模型下载和三平台文件系统行为仍需单独实测。

实际验证（2026-11-06）：`cargo test -p voice-runtime --lib models::tests --locked --offline`，14 passed、0 failed，测试执行 0.03 秒；所有文件位于 tempfile 目录，无网络下载或真实模型目录修改。该轮编译有 service 模块的未读字段 warning，不属于模型测试通过的证据范围，静态检查仍须另行完成。

## 损坏目录的启动诊断

严格 `ModelManager::open` 仍拒绝坏索引、坏条目和坏模型，原有验证不放宽。供宿主启动使用的 `open_for_runtime(directory)` 返回 `(manager, warning)`：目录本身可访问且已确认安全权限、但索引或模型数据损坏时，返回空 inventory 的只读 manager 和明确诊断；目录本身不可访问或不安全时仍返回错误。

只读 manager 持有 blocking_error。导入、下载、删除和 resolve 一律返回这一错误，不访问下载端点、不运行加载闭包、不覆盖 index、不清理 part 或删除权重。警告要求用户修复文件后重启，本次运行不会自行解除只读状态。此轮没有自动修复、备份改名或 quarantine API，也不把降级当成模型准备成功。宿主须持续显示警告并禁用录音准备状态。

新增三个临时目录测试覆盖损坏 index 的原字节、权重及 part 证据保留、所有修改操作被阻止、坏权重诊断，以及目录错误保持致命和正常目录仍可写。新增测试结果待主代理统一运行后记录。

## 模型元信息与旧索引兼容

`ModelInfo` 记录 version、language、compatibility，并在模型列表显示版本、语种、引擎、来源、许可、大小和完整 SHA-256。内置目录保留 models.lock.json 的固定 revision、语种和 CPU 兼容范围；只有完整哈希及大小一致的已验证文件才会关联该条目，不根据文件名猜版本。

旧索引缺少这三个字段时可继续打开，只在内存补齐，不在启动时覆盖旧 index。内置已知模型使用固定 revision；其他本地文件用 `sha256:<完整哈希>` 标识不可变版本，语言明确“未声明”。旧兼容范围缺失时明确需以当前构建实际加载为准；新导入只声明本机 CPU 加载经过验证，不推断其他平台或 GPU 支持。既有模型 ID 不变，保存配置仍能找到原引用。

## 启动时只读资源建议

`probe_hardware(model_directory)` 只读取架构、可用逻辑 CPU 数、Linux MemTotal/MemAvailable 和磁盘剩余空间。仅列出当前构建 CPU 后端；GPU 明确“未探测”，未知内存不填造数值。宿主在启动时缓存这份事实，界面标明启动时数值，模型加载前仍由 supervisor 做实时预算检查。

`recommend(facts, inventory)` 是纯函数：只在已有已验证模型中优先考虑符合可用内存预算的较小模型，绝不设置 model_id、启用远程、下载或修改 Config。总内存不超过 8 GiB、可用内存小于 3 GiB 或信息未知时，说明可考虑较小模型或手动远程配置。每条建议提供估算来源：权重×2，加转写 1 GiB / 整理 1.5 GiB 的运行与系统余量，整理参考默认 4096 上下文。这是粗略排序预算，不承诺实际 RSS、速度、语义质量或较大上下文一定可用。

新增测试验证旧索引字节不改写、固定目录元信息保留、内存解析异常/溢出、按可用而非仅总内存筛选、未知资源保持未知、候选仅来自 inventory，以及硬件探针不创建文件或宣称 GPU 已验证。新增测试实际结果待针对性运行后补记。

本轮元信息与资源建议的静态验证已完成：`node --check ui/app.js`、models.rs 的 rustfmt 检查及 `git diff --check` 均通过。为避免与 release 构建争锁，新增 2 项元信息兼容测试和 4 项资源建议测试交由主代理在构建后统一执行；此前 14 项通过结果不能替代这些新增测试的实际结果。
